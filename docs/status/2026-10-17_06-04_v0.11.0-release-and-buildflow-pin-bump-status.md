## e) WHAT WE SHOULD IMPROVE

1. **Version derivation must precede any release conversation.** Read CHANGELOG + FEATURES stamp + `git log vLast..HEAD` FIRST, then talk. (My v0.10.1 proposal cost a decision cycle.)
2. **Check `gh run list` before ANY release work** — the skill mandates it (Phase 4.4); I ran local gates first and found red CI mid-flight. Make it step 0 of `pre-release-check.sh` (F44).
3. **Unpinned version-floating installers in workflows are upstream-drift time bombs.** cosign v3 landed silently between v0.10.0 (2026-09-23, green) and v0.11.0 (broken). Audit every workflow for `*-installer`/action inputs that resolve "latest" (F9), and consider dependabot/renovate for action SHA bumps (F36).
4. **post-release-verify.sh verified the wrong things.** It can report 9/9 while artifacts are unsigned, taps are stale, and the docker image is missing. Extend it to check signatures, SBOM assets, tap cask version, and GHCR tag (F15) so "green" means complete.
5. **The release runbook lived only in this session's head.** The tag-failed-after-push recovery (local fallback + curated notes + backfill dispatch) is now in AGENTS gotcha 33 but the release-process doc's Rollback section doesn't cover it (F14), and the checklist doesn't warn about missing-tool skips (syft/cosign/docker) changing what a release contains.
6. **Machine-level tmpfs exhaustion is a recurring operational hazard** (BuildFlow/mutation tooling writes unbounded extractions into tmpfs). Route heavy runs through `TMPDIR` on disk, add a /tmp sweep (F20), and capture the lesson cross-project (F30).
7. **Sandbox tool gaps should fail loudly.** `kill` being a silent no-op builtin cost diagnosis rounds; surfaced to the user now, but the harness/provider should know (F21).
8. **Two overlapping 50-task lists across two reports = a split-brain waiting to happen.** HARVEST promptly (F12) and consider whether future reports should curate to 10–15 durable items instead of 50 brainstorm rows.
9. **Daemon commits bury release-relevant history.** 251 `chore:` commits between tags make every release's "what changed" investigation lean entirely on CHANGELOG. The policy question (C3) deserves an answer.
