## e) WHAT WE SHOULD IMPROVE

1. **Version constants are a 4-way manual sync** (`ExpectedGolangCILintVersion`, ci.yml pin, README line, `-schema-version` flag). Every release risks drift; one of them (the constant) was actually drifted this session. Derive from one source or add a CI consistency check.
2. **Tests hardcode version literals** — every bump requires manual test edits (this session proved it; the v2.15.0 literal guarantees a repeat).
3. **Daemon "heuristic" commits bundle whatever is dirty**, including other sessions' in-flight edits. With concurrent agent sessions this destroys attribution. Needs per-author grouping or a claim mechanism (crush-config territory).
4. **Stale context delivery:** the AGENTS.md content served to my session start predated disk by two commits. Sessions should re-verify "known" file state before judging it stale (I almost edited based on stale text; the read-first gate caught it).
5. **PATH hygiene:** duplicate golangci-lint binaries (nix store 2.14.0 + `/run/current-system/sw/bin`) produce a WARN in every test run.
6. **Editor diagnostics debt:** 4 `b.Loop()` modernization warnings (`linter_settings_internal_test.go`), 1 `infertypeargs` (`fixer_enforce_test.go:391`), and the expected `//go:build generate` gopls warning that a buildFlags tweak could silence.
7. **The release-alignment loop should be a runbook** (`docs/references/release-alignment.md`) so the next upstream release is a checklist, not an investigation.
