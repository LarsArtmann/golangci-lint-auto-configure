# Agent Guide: golangci-lint-auto-configure

Concise, enduring context for AI sessions. For detail, see the linked docs at the bottom.

## What This Is

Go CLI that auto-configures and optimizes golangci-lint configs: analyzes, detects missing linters, recommends settings, auto-fixes, replaces deprecated linters, migrates v1→v2, and emits HTML/JSON/SARIF/finding reports. **v1 config support is maintenance-only** (0 live v1 configs across 160 sibling projects; the `migrate` subcommand is kept functional but no new v1 features will be added).

## Commands (IMPORTANT — there is NO justfile)

The build system is **Nix flake + plain Go tooling**. Do not use `just` — older docs referencing it are stale.

```bash
# Build
nix build                              # reproducible build (preferred)
go build -o bin/golangci-lint-auto-configure ./cmd/golangci-lint-auto-configure

# Test (Ginkgo BDD specs, but run via go test)
# CGO_ENABLED=1 is required for -race: fresh shells may inherit CGO_ENABLED=0,
# which makes ginkgo report phantom "[Compilation failure]" for packages that
# compile fine (the real error is "-race requires cgo"). GOEXPERIMENT=jsonv2
# is required per gotcha #3 in Where to Find Detail.
export CGO_ENABLED=1 GOEXPERIMENT=jsonv2
go test -race ./pkg/... ./internal/...    # serial, ~2.5 min
ginkgo -r -p -race --skip-package=cmd/ ./pkg/... ./internal/... ./cmd/...   # parallel, ~50s (preferred)
ginkgo -r --cover                      # alternative: ginkgo directly

# Lint
golangci-lint run --config=.golangci.yml --timeout=5m

# Format (treefmt via Nix)
nix fmt                                # format Go, Nix, templ
nix flake check                        # runs format check + build + tests

# Dev shell (provides Go 1.27, golangci-lint, templ, gopls, etc.)
nix develop
```

## Tech Stack (non-obvious points)

- **Go 1.27**, Cobra CLI, charm.land log/lipgloss/fang, templ HTML reports, `go.yaml.in/yaml/v3`. go.mod declares `go 1.27` (major.minor only — house style; never let `go get` drag it to a patch floor). The `linter-autoconfigure-sdk` dependency must stay ≥ v0.7.0: v0.6.0 declared `go 1.27.1`, which forced a patch-level directive onto this repo and broke `go mod edit -go=1.27`.
- **`GOEXPERIMENT=jsonv2` is a no-op on Go 1.27** (json/v2 graduated from experiment when the toolchain moved to 1.27). The env is still set in the flake devShell, package build, and CI jobs — harmless and keeps Go 1.26-era documentation honest — but `go build`/`go test` now work without it.
- **json/v2 wire-format decoupling.** golangci-lint's JSON output uses **capitalized wrapper keys** (`"Enabled"`, `"Disabled"`) but **lowercase field keys** (`"name"`, `"description"`, `"autoFix"`). json/v2 is case-sensitive (unlike v1). Report types (`LinterInfo`, `FormatterInfo` in `pkg/types/types.go`) are tag-free (PascalCase for JSON reports). Dedicated wire-format structs in `pkg/linter/analyzer.go` (`golangciLinterEntry`, `golangciFormatterEntry`) match golangci-lint's wire format and convert to Report types after parsing.
- **Testing: Ginkgo v2 + Gomega (BDD)** — NOT standard `testing` style. Specs use `Describe`/`Context`/`It` + Gomega matchers. See `docs/references/testing-style-and-patterns.md`.
- **gogenfilter/v3**: auto-detects generated files to exclude from linting.
- **go-finding**: unified finding model (SARIF/JSON output).
- **go-error-family** (`v0.7.0`): structured error classification. Sentinel errors are registered with Families (Rejection/Conflict/Transient/Corruption/Infrastructure) in `pkg/errors/classification.go`. `ConfigError`, `ReportError`, and `MigrationError` implement the `Classified` interface (always Rejection). `AnalysisError` delegates to cause-chain sentinels for fine-grained Families. `Main()` uses `errorfamily.ExitCode(err)` for BSD sysexits exit codes instead of hardcoded `os.Exit(1)`.
- **Audit ledger** (`pkg/audit/`): append-only JSONL ledger in the OS cache dir (`~/.cache/golangci-lint-auto-configure/audit.jsonl`) that records every config mutation (linter enable/disable, formatter changes, settings pruning, re-enables, suppressed re-enables from regression loop detection). 90-day retention purge runs at the start of each configure run. Queried via the `audit` CLI subcommand (`--json`, `--since`, `--linter`, `--clear`). Disable with `--no-audit` flag or `GOLANGCI_LINT_AUTO_CONFIGURE_NO_AUDIT` env var.
- **Policy enforcement** (`pkg/policy/`): sidecar file (`.golangci-lint-auto-configure.yml`) with two sections: `disabled` (justifies intentional linter disables; when a sidecar exists, the fixer re-enables linters in `linters.disable` that lack a justification entry — anti-gaming enforcement) and `never-enable` (lists linters the tool must never add to `enable`, even when absent from both lists — the durable signal for intentionally removed linters). Tool-level disabled linters (`constants.DisabledLinters`) are always exempt. When no sidecar exists, all disables are respected (backward compatible).

## Critical Gotchas (read these — they bite)

1. **No justfile.** Despite older docs, all `just <cmd>` references are stale. Use Nix/Go directly (see Commands above).

2. **templ output is committed.** `_templ.go` files are generated from `.templ` files and committed to git (un-ignored in `.gitignore`). After editing `pkg/report/report.templ`, run `templ generate` manually before `go build`. The Nix build no longer generates templ output (it uses the committed file directly).

3. **vendorHash update after go.mod changes is automated.** A stale `vendorHash.nix` used to break `nix build` for every clone with an opaque hash mismatch. Now `scripts/vendorhash-guard.sh` parses the `got:` SRI hash from the failure: check mode prints exact paste-in instructions, `--fix` writes the hash and re-builds. CI's nix job runs the guard with `--fix` plus a `git diff --exit-code vendorHash.nix` drift check, so a stale hash fails the job with the fix command instead of a build error. Proven end-to-end on a real mismatch in a throwaway flake (2026-09-11). The buildflow nix-checker also updates the file locally ("Managed by buildflow nix-checker" header). After changing go.mod/go.sum, run `scripts/vendorhash-guard.sh --fix` and commit `vendorHash.nix` together with the dependency change. (Reminder: run inside `nix develop` or export `GOEXPERIMENT=jsonv2` first — the code imports `encoding/json/v2` which won't compile without it.)

4. **go-finding & gogenfilter replace in Nix.** `go.mod` uses published versions. Nix's `mkPreparedSource` (from go-nix-helpers) injects `replace` directives pointing to https-fetched public local copies (the Go proxy doesn't cache these repos). `go mod tidy` runs ONLY in the go-modules FOD (has network via `__noChroot`); the main derivation sets `GOFLAGS=-mod=mod` to auto-reconcile from the FOD's proxy cache. Config-level findings use `Line: 1` (go-finding requires `Position.Line > 0`).

5. **Error classification via go-error-family.** `pkg/errors/classification.go` has an `init()` that registers all sentinel errors with their `errorfamily.Family`. To add a new sentinel: add it to the map in that file. `ConfigError`, `ReportError`, and `MigrationError` implement `Classified` → `Rejection` (type-level, checked before sentinels). `AnalysisError` does NOT implement `Classified` — its sentinels in the cause chain (e.g. `ErrVersionTooOld`) handle classification. Exit codes: Rejection/Conflict → 1, Transient → 75, Corruption → 65, Infrastructure → 69. `--json-errors` outputs via `errorfamily.Wrap().JSON()` (snake_case canonical schema with family/code/message/context/retryable).

6. **The declarative reconciler is the ONLY engine** (ADR-017; legacy pipeline deleted 2026-10). `FixConfig` runs collect → normalize → render → plan → apply (`pkg/linter/converge.go`, `fixer_converge.go`); counts, dry-run reports, and audit entries are all projections of the same `Change` records (`AuditActionsFor`), so there is no counter to drift. The parity corpus (`TestParityCorpusConverge`) proves byte-identical output vs. the legacy goldens on 11 fixtures. The old imperative mutator pipeline (`applyAllFixes`/`applyAndSave`/`configChangeRecorder`) is gone — there is no `SetEngine` or engine switch anywhere. The fixer converges `issues.max-issues-per-linter` and `issues.max-same-issues` to `0` (unlimited) ALWAYS (since 2026-10-16): any non-zero value is updated, and absent keys are added explicitly — an absent key would let golangci-lint fall back to its own truncating defaults (50/3). The yaml/toml tags on those two fields deliberately drop `omitempty` so explicit zeros round-trip; presence (absent vs explicit 0) is tracked via `IssuesConfig.SetSourceIssuesKeys`/`CarriesIssuesKey`, captured by the YAML/TOML loaders (JSON stays presence-unknown because its tags omit zeros — tracking it there would churn forever). **Lint/apply drift is structurally dead**: `Fixer.PlanDeviations`/`Evaluate` run the same plan report-only, and `finding.DeviationsToFindings` converts each Change into one finding. **With one accounting rule** (2026-10-17 incident): `finalizeConvergence` must UNION phase-one's persisted changes with Converge's in-memory normalizer changes by `Change.Key()` (`mergeNormalizerChanges` in `fixer_converge.go`) — never overwrite. The redundancy pass (`RemoveRedundancies`, lll dies with golines) runs ONLY inside `Converge`, so the old `result.NormalizerChanges = normalizeChanges` overwrite silently discarded it: apply reported "already converged" while detect still flagged the drift, producing a warning finding no repair could clear. Specs: `fixer_supersession_apply_test.go` (apply parity + one-round convergence), `fixer_converge_merge_internal_test.go` (union table).

7. **Curated settings ride with the policy table (ADR-017).** Settings are `VersionedSettings` blocks ON the policy records (`pkg/constants/linter_policy_table.go`); the typed settings structs live in `pkg/constants/linter_settings.go` and the desired renderer's `renderLinterSettings` collects the version-valid blocks (`DesiredConfig.LinterSettings`). `--force-settings` flips the merge STRATEGY table to PreferDesired (`StrategiesFor` in `pkg/linter/merge.go`) — no flag threading through mutators (the old `injectDefaultSettings` mutator is deleted with the legacy engine). **Friction-driven defaults**: `exhaustruct` excludes stdlib structs, `gosec` excludes G304/G115, `errcheck` has `check-type-assertions` + curated `exclude-functions` (Close, Fprint*), `funlen` uses house style 200/100 (diverges from upstream 60/40), `mnd` excludes test files (`_test.go`) and common numbers, `wrapcheck` has stdlib sig regexps (fmt, errors, slices, maps, sort, time, os, io, strings, strconv, path, filepath), `varnamelen` has typed `ignore-decls` (db, tx, w, r, etc.), `gocognit`/`gocyclo`/`nestif`/`goconst` have calibrated thresholds, `tagalign` has curated tag ordering (binding, json, yaml, xml, toml, validate, mapstructure). **Orphaned settings pruning**: the closing plan removes settings for linters neither enabled nor disabled (dead weight when `default: none` is used).

8. **Capability probe gates every recommendation on the pinned binary (issue #15).** A linter the detected golangci-lint cannot name (plugin linters like gohumanize on stock binaries — no version interval expresses plugin presence) would make the whole config unloadable ("unknown linters"), for BOTH `enable` and `disable` lists. Three layers, all in `pkg/linter/`: (a) `Analyzer.ProbeKnownLinters` runs `golangci-lint linters --json` config-independently (temp cwd, cached per Analyzer) and `Env.BinaryKnown` carries the vocabulary; (b) the renderer (`shouldRender`/`settingsApply`) withholds unknown-to-binary linters and reports them as `DesiredConfig.Unsupported` → apply-mode warning + `unsupported-recommendation` finding (rule in `pkg/finding/evaluation.go`); (c) `RemoveUnknownLinters` (a normalizer, runs pre-analysis in phase one) heals configs already poisoned by older tool versions — removal is audited as `removed-from-enable`/`removed-from-disable`. Empty probe result = unknown binary = fail open (no gating, no removal). `Analyzer.VerifyConfigLoads` is the post-apply tripwire: after every real save the fixer re-runs `golangci-lint linters` on the written config and warns loudly if it cannot load (best-effort; check mode is the gating surface). When `AnalyzeConfig` fails on a poisoned config, `collectAnalyzerEnabled` falls back to the probe's default-enabled set to avoid bogus re-declaration churn. Specs: `desired_capability_test.go`, `capability_e2e_test.go` (skips on a custom binary that carries gohumanize), `probe_internal_test.go`, `env_capability_internal_test.go`, `normalize_unknown_internal_test.go`.

9. **Config auto-creation requires a git repo.** `configure` creates a default `.golangci.yml` if missing. Git is mandatory for version-control safety.

10. **DI is manual.** No `internal/di/` directory (older docs lie). Dependencies wired manually in CLI commands. No DI framework.

11. **Linter priority data is static constants.** Priorities live in `pkg/constants/linter_priorities.go` + reasons in `linter_reasons.go`. Not dynamically computed from golangci-lint. To add/change a linter, edit both files (and `presets.go`/`rules.go` if relevant). To add/change a linter, edit its ONE record in the policy table (`linter_policy_table.go`, generated by `cmd/gen-policy-table` from the frozen views-goldens). The legacy maps in `rules.go` are now VIEWS over the table: `DisabledLinters` (currently `funcorder`, `noinlineerr`), `NeverAutoEnableLinters` (currently `depguard`, `exhaustruct_v5`), and `PragmaticNoiseLinters` — the last is DERIVED from friction evidence (`types.DeriveTier`, threshold `types.PragmaticNoiseFrictionThreshold` = 0.8 nolints/config), not hand-maintained. Disabled linters must never have entries in `LinterPriorities` or `LinterReasons`; NeverAutoEnable linters MUST have entries (they can be manually enabled). Enforced by data integrity tests + `scripts/validate_linter_data.go`.

12. **Versioning is self-initializing.** `pkg/version/` reads ldflags with `runtime/debug.ReadBuildInfo()` fallback. `cli.Version` self-inits — no manual setup. All build targets (Nix, CI) inject via ldflags. **Critical:** the ldflags must target `github.com/larsartmann/golangci-lint-auto-configure/pkg/version.*`, NOT `main.*` — the version vars live in `pkg/version/version.go`, not in `main.go`. The Nix flake and Dockerfile already target the correct path. `.goreleaser.yaml` was fixed in the v0.6.0 post-release cleanup (it had been targeting `main.*` since the versioning overhaul, causing every GoReleaser binary to show the commit hash instead of the version number).

13. **Struct tag case policy.** Enforced by **tagliatelle** in `.golangci.yml` (`json: pascal`, `yaml: kebab`, `toml: kebab`). Three type families:

    | Family                                                                                                                                                                 | `json`/`cbor`                                               | `yaml`/`toml`           | Why                                                       |
    | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------- | ----------------------- | --------------------------------------------------------- |
    | **Report types** (`pkg/types/types.go`: `ConfigAnalysis`, `LinterInfo`, …; `pkg/report/json_report_generator.go`: `JSONReport`; `pkg/config/merger.go`: `MergeResult`) | **PascalCase** — tags stripped, Go field names pass through | n/a (no yaml/toml tags) | Zero-tag-cost: Go-native, no browser consumers            |
    | **Config types** (`pkg/types/config_types.go`: `Config`, `RunConfig`, `LintersConfig`, …)                                                                              | **kebab**                                                   | **kebab** (locked)      | Round-trips `.golangci.yml` schema; one struct = one case |
    | **External format types** (`LinterList`, `golangciLintOutput`, `golangciLintVersion`, `GolangciLintIssue`)                                                             | **as-is** (matches golangci-lint wire format)               | n/a                     | Must match external JSON shape; tagliatelle-excluded      |

    **musttag linter:** `Marshal`/`Unmarshal` of tag-free report structs need `//nolint:musttag`. Test files are excluded from musttag in `.golangci.yml`.

14. **No committed `.buildflow.yml`; treefmt owns formatting.** The repo has no `.buildflow.yml` (an older gotcha referenced one; it was removed). Nix formatting is handled by the treefmt step (`nix fmt`), which respects exclude patterns — never run raw `nixfmt .`, which scans `.direnv/flake-inputs/` (symlinked third-party nix caches). GitHub Actions workflows set `GOEXPERIMENT: jsonv2` at the job level for all Go-compiling jobs (`test-and-build`, `lint`, `govulncheck`, `release`; inert on Go 1.27 but kept intentionally — removal is a tracked TODO, USER-GATED like the flake devShell env). The `.golangci.yml` `run.build-tags` entry `goexperiment.jsonv2` was removed 2026-10-07 (own lint green at 0 issues) — the env var keeps golangci-lint's internal builds working without the tag; the CI lint job runs golangci-lint v2.14.0 and the test job installs it (specs fail in CI without the binary).

15. **`WrapClassified` returns `*errorfamily.Error`, not `error`.** Callers that pass a potentially-nil error MUST check for nil first (`if err == nil { return nil }`) before calling `WrapClassified`/`WrapClassifiedf`. Otherwise, nil `*errorfamily.Error` gets boxed into a non-nil `error` interface (the typed-nil interface pitfall), causing the caller's error check to always be true. Two bugs from this were fixed: `RunFmtCommand` always reported failure, and `validate` never reported success. The return type was kept as `*errorfamily.Error` (intentional) so callers can access classified methods.

16. **Disable-reason enforcement is opt-in via sidecar.** When `.golangci-lint-auto-configure.yml` exists next to `.golangci.yml`, the fixer re-enables any linter in `linters.disable` that lacks a justification entry in the sidecar. Without a sidecar, all disables are respected. This prevents AI agents from silently disabling linters to game the lint gate. Tool-level disabled linters (`constants.DisabledLinters`: funcorder, noinlineerr) are always exempt from enforcement.

17. **Audit ledger is best-effort and lives outside the git tree.** The JSONL ledger at `~/.cache/golangci-lint-auto-configure/audit.jsonl` records every config mutation. Failures to write are logged but never block the configure run. Dry runs never emit entries. Query with the `audit` subcommand; purge with `--clear` or automatically via 90-day retention.

18. **json/v2 `omitempty` no longer omits `false`/`0`.** Under `encoding/json/v1`, `omitempty` dropped false bools, zero ints, and empty strings. Under `encoding/json/v2` it only omits nil pointers/interfaces and empty slices/maps/arrays/strings. To omit Go zero values (false, 0, ""), use **`omitzero`** instead. Report types (`LinterInfo.Fast`, `LinterInfo.AutoFix`, `FormatterInfo.AutoFix` in `pkg/types/types.go`) use `omitzero` for exactly this reason. Resolved 2026-09-11: the seven `bool`/`int` fields in `pkg/types/config_types.go` (`run.issues-exit-code/tests/concurrency`, `output.show-stats`, `linters.exclusions.warn-unused`, `issues.max-issues-per-linter/max-same-issues`) now use `omitzero` on their `json:` tags only. The five non-issues fields keep `omitempty` on yaml/toml (v1-style drop-zero semantics); the two issues-cap fields DROPPED yaml/toml `omitempty` (2026-10-16) so their always-zero values are written explicitly (see gotcha 6). Pinned by the omitzero spec in `pkg/config/loader_test.go`. See `docs/references/json-v2.md`.

19. **`os.IsNotExist` does not unwrap `fmt.Errorf %w` chains.** It only type-switches on raw `*PathError`/`*SyscallError`, so it returns `false` for any wrapped error. When a function wraps its error (e.g. `audit.ReadAll` wraps with `fmt.Errorf("open audit ledger %q: %w", ...)`), use `errors.Is(err, os.ErrNotExist)` instead, which unwraps correctly. The 8 other `os.IsNotExist` call sites check raw `os.Stat`/`os.ReadFile` errors (never wrapped) and are safe; only the wrapped-error site needed fixing (`internal/cli/cmd_audit.go`, `displayAuditEntries`).

20. **`--pragmatic` flag drops noise linters from the enable set — by threshold, not by list.** The pragmatic-noise tier derives from each record's `Friction` evidence at table load (`types.DeriveTier` in the constants init path; ratio ≥ 0.8 promotes an UNMANAGED linter; explicit Disabled/NeverAutoEnable tiers win over measurement). Today that yields exactly `gochecknoglobals` (5.1), `wrapcheck` (1.8), `ireturn` (1.3), `funlen` (0.83) — pinned by `pkg/constants/tier_derivation_test.go`. The converge renderer (`tierAdmits` in `pkg/linter/desired.go`) skips the tier when `--pragmatic` is set. Off by default; default behavior is byte-identical. `gochecknoglobals` has **no config knobs** in golangci-lint v2, so `--pragmatic` is the only way to opt out without manually disabling it. `exhaustruct` (formerly the 5th pragmatic linter at friction 6.5) is now in `NeverAutoEnableLinters` (as `exhaustruct_v5`) — it is **never** auto-enabled by any code path, but is respected with curated stdlib `ignore-patterns` when a user manually adds it. Since 2026-09-11 `exhaustruct` is also in `DeprecatedLinters` (deprecated in golangci-lint v2.13.0): the fixer replaces it with `exhaustruct_v5`, migrates the settings block, and the `KnownBadSettingsKeys` pass renames v4's `exclude` to v5's `ignore-patterns` (the curated default was ported verbatim). **golangci-lint v2.13 deprecates `exhaustruct` in favor of `exhaustruct_v5`** (warning on every lint run since 2026-09-10). **Since 2026-10-13 the deprecation sweep also covers `linters.exclusions.rules[].linters`** (`cleanupExclusionLinters` in `pkg/linter/fixer_deprecated.go`): the enable-set swap and the pre-flight sweep both left exclusion rules untouched, so 86/157 fleet configs carried the dead predecessor there (deprecation warning every run; hard config break when upstream deletes the name). The sweep runs on EVERY configure pass (independent of enable state, so post-migration configs heal), is version-gated like the enable swap, renames + dedupes with available replacements, drops removed-linter names (text/source-scoped rules die with the linter — an unscoped pattern would suppress findings from every linter; path-scoped rules survive), and audits as `exclusion-linter-renamed`/`exclusion-linter-removed`. Specs: `fixer_deprecated_exclusions_test.go` + `TestCleanupExclusionLinters_VersionGated`.

21. **`house` formatter preset and `CoreFormatters` both lock the validated formatter stack.** `PresetFormatters["house"]` and `CoreFormatters` (`config.go:30`) are both `{goimports, gofumpt, golines}` — the stack across 128/160 sibling projects, with `gci` dropped 2026-10-11 (too many projects rejected its import-group reordering; it stays in `FormatterOrder`/`FormatterData` so manual enablement still works and gets canonical ordering). `CoreFormatters` is the runtime default for non-preset configure runs; `house` is the preset that composes it with `minimalLinters`.

22. **Golden snapshot test for HTML reports.** `pkg/report/golden_test.go` compares rendered HTML against a committed golden file (`pkg/report/testdata/golden/report.html`). When you change `pkg/report/report.templ`, the test will fail. Regenerate with `UPDATE_GOLDEN=1 go test ./pkg/report/...`, then review the diff before committing. The golden file is committed to git (not gitignored).

23. **Coverage threshold gate is a Go program, not a bash script.** `cmd/coverage-check/main.go` replaces the old `scripts/coverage-check.sh`. CI runs it via `go run ./cmd/coverage-check -min=65 -profile=coverage.out`. It has BDD tests (`cmd/coverage-check/main_test.go`) for the `parseTotalPercentage` parsing logic. The old bash script was deleted — do not recreate it.

24. **Markdown linting is a separate CI workflow.** `.github/workflows/markdown-lint.yml` runs `markdownlint-cli2-action` on `.md` files (excluding `docs/status/`, `docs/archive/`, `vendor/`, `CHANGELOG.md`). Config lives in `.markdownlint-cli2.jsonc` (allows `<details>`/`<summary>` HTML; disables line-length, bare-URLs, emphasis-as-heading, and table-column-style rules — the latter two because historical planning/review reports legitimately use bold summary lines and unaligned pipes). The main CI workflow (`ci.yml`) has `paths-ignore: **/*.md`, so markdown changes don't trigger Go CI. `ci.yml` also has `workflow_dispatch` (re-enabled 2026-09 after being manually disabled since July 2026) so it can be triggered manually with `gh workflow run ci.yml`.

25. **Flags struct replaces package-level globals.** All CLI flag values live in a single `Flags` struct (`internal/cli/flags.go`), created in `Main()` and threaded through `*CommandBuilder` to every command. Never add package-level `var` for flags — `gochecknoglobals` enforces this. Global persistent flags are bound in `registerGlobalFlags()`; command-specific flags (e.g., `--check`, `--no-audit`, `--pragmatic`) are bound in the command's flag setup. The migrate command (`internal/cli/cmd/migrate.go`) is the exception: it reads flags from `cmd.Flags()` at runtime and binds its unique `--skip-validation` locally (no `Flags` struct, since it lives in a sub-package that can't import `internal/cli` without a circular dependency).

26. **SettingsMap centralizes `map[string]any` settings access.** `pkg/types/settings_map.go` wraps `map[string]any` with `AsSettingsMap()`, `IsEmpty()`, and `Clone()`. Use `types.AsSettingsMap(v)` instead of raw `v.(map[string]any)` type assertions in clone/merge/validate/prune code paths. BDD specs in `settings_map_test.go`.

27. **`erraudit` is a manual review tool, NOT a CI gate — do NOT suppress its findings with `//nolint`.** A full `erraudit ./...` review (2026-07-26) found 38 findings (0 `legacy_as`/`legacy_is`, 5 `silent_swallow`, 22 `ignored`, 11 `generic_return`). Four were genuine bugs and were fixed: (a) `pkg/audit/ledger.go` `rewriteLedger` now logs the marshal error via `slog.Warn` instead of a bare `continue` that silently dropped audit entries during compaction; (b) `pkg/detection/detector.go` `scanFileForSwaggo` + `hasSwaggoInCode` propagate `scanner.Err()` (wrapped via `errorfamily.WrapTransient`) to the public `HasSwaggo()` caller; `hasMainPackage`/`hasAPICodePatterns` are best-effort private helpers (called from `detect()` which returns only `ProjectType`) — per-file scanner errors are logged via `slog.Debug` and swallowed (return nil) to preserve walk resilience so one bad file does not abort detection, and walk-level errors are captured and logged at the call site; (c) `pkg/report/generator.go` `GenerateReport` uses a named return `(err error)` so a deferred `outputFile.Close()` failure on the write path is captured instead of ignored. The remaining 33 findings are intentional/false-positive and left as-is: `ignored` covers idiomatic Go (cobra flag getters, completion-script generation, `crypto/rand.Read`, deferred read-path closes, best-effort detection heuristics with no logger); `generic_return` is advisory only since errors are classified at command boundaries via go-error-family, not per-function types; `silent_swallow` covers logged-and-continue graceful degradation in the config merger. **Do not try to drive erraudit to zero with `//nolint:erraudit`:** it conflicts with the actual CI gate — erraudit only honors _inline_ `//nolint:erraudit` (a directive on the line _above_ does NOT suppress), but golines (max-len 120) cannot fit `//nolint:erraudit // reason` on long signatures like `AnalysisToReport` (~100 chars), and nolintlint needs a reason, while golangci-lint also emits a "Found unknown linters: erraudit" warning. 28. **`run.go` is written as major.minor and capped at golangci-lint's build Go version.** golangci-lint refuses to load a config whose `run.go` is newer than the Go version it was built with ("the Go language version (goX) used to build golangci-lint is lower than the targeted Go version"). `updateGoVersion` (`pkg/linter/fixer_config.go`) therefore (a) strips the patch from the local version ("1.27.1" → "1.27", avoiding a config rewrite on every toolchain patch bump) and (b) caps the value at the golangci-lint build Go version detected by `CheckVersion` (JSON `goVersion` field, text "built with goX.Y.Z" fallback; stored via `Analyzer.GetDetectedGoVersion()`, threaded through the `types.LinterAnalyzer` interface). When capping fires, a warning tells the user to upgrade golangci-lint. Unparsable local versions (e.g. `devel` toolchains) leave `run.go` untouched instead of writing garbage. Normalization/comparison helpers are exported from `pkg/types/version_type.go` (`NormalizeGoMajorMinor`, `CompareGoMajorMinor`); default-config creation normalizes too (`pkg/config/loader.go`). A config whose run.go ALREADY exceeds the binary (unloadable by golangci-lint) is repaired pre-analysis by `rescueOverspecifiedRunGo` (`pkg/linter/fixer_run_go_rescue.go`), audited as `rescued-run-go`; `--check`/`--dry-run` instead fail with the classified `config.run_go.newer_than_binary` error and leave the file untouched. The project's own go.mod `go` directive is a separate signal: `warnIfGoModExceedsBinary` (`readGoModGoDirective`/`scanGoDirective`, block-aware parser that ignores require-blocks and `toolchain` lines) warns in ALL modes when go.mod declares a newer Go than the binary was built with — go.mod is NEVER rewritten, matching the error template's promise. The `config.run_go.newer_than_binary` Fix line leads with the concrete repair command (`configure --config <path>`), and `analyze --verbose` prints a Go doctor line (local Go vs golangci-lint build Go, `doctorLine()` in `internal/cli/cmd_analyze.go`). Specs: `go_version_internal_test.go`, `fixer_run_go_rescue_internal_test.go`, `fixer_run_go_gomod_internal_test.go`, `pkg/types/go_version_test.go` (plus fuzz targets in `version_fuzz_test.go`).

2. **`gohumanize` is a module plugin, recommended project-specific AND binary-gated.** `gohumanize` is a golangci-lint v2 module plugin (not bundled with stock golangci-lint; requires a custom binary built via `golangci-lint custom` + `.custom-gcl.yml`). TWO gates must pass before the fixer writes the enable entry: the project's `go.mod` must import `github.com/dustin/go-humanize` (tech gate: `RequiresTech("go-humanize")` + `Detector.HasGoHumanize()` in `pkg/detection/detector.go`), AND the detected binary must actually carry the linter (capability probe, gotcha 8 — the dependency gate alone shipped entries stock binaries reject, the issue #15 loop). When both pass, only the bare `linters.enable: [gohumanize]` entry is written — no `linters.settings.custom.gohumanize` block, because emitting that block without a custom binary would break stock golangci-lint the same way. On a stock binary the recommendation is withheld and surfaced as an `unsupported-recommendation` warning/finding; a config already carrying the entry is healed (removed) by the normalizer. Users who want the curated rule subset (H001/H002/H003/H007) must configure the custom binary themselves (see gohumanize-linter docs). The tool's own repo suppresses one self-detection finding with a documented `//nolint:gohumanize` in `scripts/validate_linter_data.go` (the validator's humanized output triggers H004 on itself); do not remove it without re-triaging.

3. **Regression loop detection + `never-enable` sidecar section.** In golangci-lint v2, removing a linter from `enable` (without adding to `disable`) is the documented way to disable it. But `configure` treated this omission as "user forgot" and re-added the linter, creating an infinite loop (user removes -> tool re-adds -> user removes again). Two mechanisms now prevent this:

   **(a) Automatic cycle detection via audit ledger** (`enableRecommendedLinters` in `pkg/linter/fixer.go`): before adding a linter to `enable`, the fixer checks if the audit ledger has an `ActionAddedToEnable` entry for it (via `audit.PreviouslyAutoEnabled` / `Ledger.PreviouslyAutoEnabled()`). If so, the tool skips re-adding and logs a warning suggesting `linters.disable` or the `never-enable` sidecar section. This breaks the loop automatically on the second cycle. Best-effort: requires the audit ledger (disabled with `--no-audit`), is per-machine, and is purged after 90 days. The suppression is recorded as `ActionSuppressedReEnable` in the ledger (visible via `audit` subcommand).

   **(b) Durable `never-enable` sidecar section** (`pkg/policy/policy.go`): the sidecar `.golangci-lint-auto-configure.yml` now supports a `never-enable:` section (kebab-case YAML key) alongside the existing `disabled:` section. Linters listed there are never added to `enable`, period. This is the durable, committed-to-git signal that works across machines and CI. Example:

   ```yaml
   never-enable:
     godoclint:
       reason: "demands per-package godoc; this repo documents per-file"
       category: convention
     ireturn:
       reason: "every component returns templ.Component by design"
       category: convention
   ```

   The `never-enable` check is applied in **both** code paths: recommendation (`enableRecommendedLinters` in `fixer.go`) and anti-gaming enforcement (`tryReEnableLinter` in `fixer_enforce.go`). Without the enforcement check, a linter in both `disable` (unjustified) and `never-enable` would be re-enabled by enforcement, defeating the protection. `never-enable` takes priority over all other mechanisms. It also bypasses deprecation replacement migration (`deprecatedLinterHandler.neverEnable` in `fixer_deprecated.go`): when the sidecar lists the REPLACEMENT, the deprecated predecessor is still removed (cleanup) but the replacement is NOT added and its settings are NOT migrated. `NeverAutoEnableLinters` deliberately does NOT apply here — replacing a linter the user manually enabled is a migration of their explicit choice, not an auto-enable. Specs: `fixer_never_enable_test.go`.

   The `Fixer.reader` field (type `ledgerReader`, duck-typed interface with `PreviouslyAutoEnabled() map[string]bool`) is set in `SetLedger` via type assertion. Both `*audit.Ledger` and `audit.NoopRecorder` satisfy it. When the recorder doesn't implement it (e.g., test doubles without the method), cycle detection is silently disabled.

4. **YAML indentation is preserved on save.** `SaveConfig` reads the existing file and calls `detectYAMLIndent()` to find the indent width of the first indented line. The `yaml.Encoder.SetIndent(n)` controls output indentation. `detectYAMLIndent` rejects tab-indented lines (invalid YAML) and widths outside `[1, maxValidYAMLIndent(8)]`, falling back to `defaultYAMLIndent` (2). New files default to 2-space. Tests in `pkg/config/indent_internal_test.go`. The migration path (`pkg/migration/yaml_loader.go`) already used `SetIndent(2)` as a fixed default.

5. **`--force-settings` overwrites stale linter and formatter settings.** Both `injectDefaultSettings` and `injectDefaultFormatterSettings` accept a `force bool` parameter. When `false` (default), existing non-empty settings are preserved (idempotency guard). When `true` (`--force-settings` flag), the curated defaults overwrite whatever the user had. This solves the self-config trap: the tool's own `.golangci.yml` can never be cleaned up by re-running without `--force-settings` because the idempotency guard prevents overwriting. The flag threads: `Flags.ForceSettings` → `Fixer.SetForceSettings()` → `updateConfigFromSets(forceSettings)` → `injectDefaultSettings(force)` / `injectDefaultFormatterSettings(force)`.

6. **Exclusion-rule merge uses RuleKey dedup in both paths.** The fixer path (`updateExclusionRules` in `pkg/linter/fixer_config.go`) and the config-merger path (`mergeLintersExclusionRules` in `pkg/config/merger_linters.go`) both now merge linter lists by `RuleKey()` (`Path|Text|Source`) instead of blindly appending duplicate rules. When a default/secondary rule matches an existing rule by key, their linter lists are unioned (`mergeExclusionLinters` in the fixer, `mergeUniqueItems` in the merger). This ensures stale configs receive newly-added default linters without duplicating rules. Previously the merger path had no dedup at all (split-brain).

7. **`linter_settings_generated.go` is generator output, formatted at generation time.** `cmd/generate-settings` regenerates it from `pkg/constants/schema/golangci-lint.jsonschema.json` (`go run ./cmd/generate-settings -schema=... -output=...`). The generator runs output through `go/format` before writing and emits `struct{}` for empty settings structs — both required to keep treefmt (gofumpt) green, since treefmt checks all `.go` files even under the file's `//go:build generate` tag. Regression-guarded by `cmd/generate-settings/main_test.go`. The file is a reference for hand-maintaining the curated structs in `pkg/constants/linter_settings.go`; it does not compile into the normal build, and its gopls "No packages found" warning is expected. 8. **Known-bad settings keys self-heal on configure.** `constants.KnownBadSettingsKeys` (`pkg/constants/config.go`) maps schema-invalid settings keys this tool once emitted to their valid names (currently `goconst.min-length` → `min-len`, the 2026-09-11 schema bug). `normalizeKnownBadSettingsKeys` (`pkg/linter/fixer_config.go`, called at the top of `updateConfigFromSets`) renames such keys on every configure run, so configs broken by older tool versions self-heal.
